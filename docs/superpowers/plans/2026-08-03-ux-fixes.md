**Goal:** four small, independent UX fixes surfaced by the user's first manual testing pass.

## Item 1 — hide archived symbols from the main markets list

`frontend/src/pages/MarketsPage.tsx` always renders an inline "Archived: … — restore" row
alongside the active list. Change to a local view toggle (`active` / `archived`) within the same
page — no new route, no backend change (`GET /api/market/symbols` already returns everything with
an `archived` flag; `POST /api/market/symbols/:symbol/archive` already handles both directions).

- Active view: current list, unchanged, with the existing per-symbol Archive action.
- Archived view: the rows currently shown inline, each with a Restore button — just gated behind
  the toggle instead of always visible.

**Files:** `frontend/src/pages/MarketsPage.tsx`, `frontend/test/markets-page.test.tsx`.

## Item 2 — populate `symbols.name`/`market`, show it in the UI

`symbols.name` exists in the schema but nothing ever writes it. `yahoo-finance2`'s `quote()`
response (already fetched every poll cycle by `MarketDataService.poll`) carries `longName`/
`shortName` — no new Yahoo call needed.

- Widen `QuoteFetcher`'s return shape (`backend/src/market/data.ts`) to
  `{ price: number; currency: string; name?: string }` — additive, existing fakes/mocks that omit
  `name` still typecheck (`name?` optional).
- `yahooFetcher` (`backend/src/market/yahoo.ts`) sets `name: r.longName ?? r.shortName`.
- `MarketDataService.poll()` backfills: `UPDATE symbols SET name = ? WHERE symbol = ? AND name IS
  NULL` when a fetched quote carries a name and the symbol row already exists (tracked). Never
  overwrites an existing name, never inserts a new symbols row (that stays `SymbolRegistry.track`'s
  job) — `poll()` already touches `db` directly for `price_bars`, so this is consistent scope.
- Frontend: `SymbolRow` already has `name`/`market` typed. Show `name (market)` next to the ticker
  in `MarketsPage.tsx`'s symbol list — the only place symbols currently render as bare tickers.
  (The watchlist inputs in `ConfigPanel.tsx`/`NewRoundPage.tsx` are plain comma-separated text
  fields with no symbol lookup at all — out of scope here, not touched.)

**Files:** `backend/src/market/data.ts`, `backend/src/market/yahoo.ts`,
`backend/test/market-data.test.ts` (or wherever `MarketDataService.poll` is tested),
`frontend/src/pages/MarketsPage.tsx`, `frontend/test/markets-page.test.tsx`.

## Item 4 — cron presets + human-readable next-run preview

Both `ConfigPanel.tsx` and `NewRoundPage.tsx` take raw cron expressions in a `<textarea>`, one
per line, with no feedback on what they mean.

- Add `cron-parser` (already a backend dep, pure JS, safe client-side — no network round trip,
  no debounce needed) as a **frontend** dependency too.
- Small shared helper `frontend/src/lib/cron.ts`: a fixed preset list (e.g. "ASX open weekdays",
  "Hourly during ASX+US sessions", "Once daily at close") mapping to canonical cron strings, plus
  `nextRunLabel(expression: string, now = new Date()): string | null` using
  `CronExpressionParser.parse(expression, { currentDate: now, tz: 'Australia/Sydney' })` (same
  timezone constant the backend scheduler uses), returning a formatted next-fire time or `null`
  for an unparseable expression.
- UI: preset buttons above the textarea that insert/append the canonical string; the textarea
  stays as the raw/advanced escape hatch (unchanged parsing on save — `checkinCron` is still
  newline-split). Below the textarea, one "next run: …" line per non-empty cron line, computed
  live from `nextRunLabel`; an invalid line shows "can't parse this schedule" instead of crashing.

**Files:** `frontend/package.json`, `frontend/src/lib/cron.ts` (new), `frontend/test/cron.test.ts`
(new), `frontend/src/pages/round/ConfigPanel.tsx`, `frontend/src/pages/NewRoundPage.tsx`,
`frontend/test/round-config.test.tsx`, `frontend/test/new-round.test.tsx`.

## Item 5 — plain-English guardrail helper text

`ConfigPanel.tsx` and `NewRoundPage.tsx` both show bare `Stop-loss %` / `Max position %` /
`Drawdown pause %` inputs under a "Guardrails — blank disables" legend with no explanation. The
two fieldsets are already fully duplicated (no shared component) — add matching `<small
className="muted">` helper text under each input in both places, consistent with the existing
duplication rather than introducing a new shared component for three fields.

- Stop-loss %: "Sell automatically if the price falls this far below what you paid. Leave blank
  to disable — but note a blank stop-loss means a bad position can run unchecked."
- Max position %: "Cap how much of the starting balance can sit in one symbol at cost. Blank
  means no cap."
- Drawdown pause %: "Pause the round (new buys blocked, protective stops keep firing) once total
  equity has fallen this far below the starting balance. Blank means it never auto-pauses."
- Keep the existing invariant note ("blank means disabled, never 0 — a 0% stop-loss sells
  instantly") visible near the fields, not just in a code comment.

**Files:** `frontend/src/pages/round/ConfigPanel.tsx`, `frontend/src/pages/NewRoundPage.tsx`,
`frontend/test/round-config.test.tsx`, `frontend/test/new-round.test.tsx`.
